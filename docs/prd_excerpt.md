# PRD Excerpt｜09:35 开盘承接确认工作流

## 1. 功能定位

09:35 开盘承接确认是 A 股投资辅助决策 Agent 中的高风险动作降级功能。它解决的问题不是让系统更早追强，而是在缺少完整 A2 竞价数据时，把 09:28 的高风险判断降级为 09:30-09:35 的承接验证。

该功能服务于盘中决策辅助场景：系统只输出研究计划、风险边界和人工确认点，不自动下单，不承诺收益。

## 2. 背景与问题

开盘前 09:15-09:25 的竞价数据可以帮助判断强弱，但公开或普通数据源通常缺少竞价金额、撤单、排队和封单细节。如果系统在缺少这些字段时仍输出 09:28 追强计划，容易把高开、情绪和单一题材误判为可执行机会。

核心问题：

1. A2 数据缺失时，系统不能把开盘前强势当成事实充分。
2. 用户在开盘前后容易受到涨幅和题材刺激，要求系统给出高置信动作。
3. 需要一个明确的产品机制，把缺证据的机会转化为 post-open confirmation，而不是简单忽略或继续追强。

## 3. 目标用户与场景

| 用户类型 | 典型场景 | 需要系统解决的问题 |
| --- | --- | --- |
| 主动交易者 | 09:28 看到个股高开、板块活跃 | 判断是否有权限追强，或是否必须等承接 |
| 投研助理 | 快速整理开盘前后多个关注标的 | 将候选标的按数据可用性和风险权限分层 |
| 个人投资者 | 持仓或关注股大幅高开 | 判断是持有、减仓、观察还是等待确认 |

## 4. 用户故事

1. 作为盘中交易者，当系统缺少 A2 竞价明细时，需要明确知道“不能 09:28 追强”的原因。
2. 作为投研辅助用户，需要在 09:35 获得一份承接确认清单，包括价格位置、成交、板块共振和风险收益比。
3. 作为风险敏感用户，需要任何买入或加仓计划都带有触发、止损、目标 R、失效条件和“不交易条件”。

## 5. 功能范围

包含：

1. 读取用户关注板块、个股和当前持仓。
2. 运行数据健康门，检查 A0/A1/A2/B1 是否满足动作权限。
3. 在缺 A2 时自动禁止 09:28 追强。
4. 生成 09:30-09:35 承接确认字段和人工核验清单。
5. 对通过确认的标的生成低权限或正常权限计划。
6. 对未通过确认的标的输出观察、减仓或放弃条件。
7. 写入 prediction/outcome/behavior 日志字段，支持后续复盘。

不包含：

1. 不接入券商自动交易 API。
2. 不对收益做确定性承诺。
3. 不把资金流代理写成真实机构意图。
4. 不在缺关键数据时用模型补全行情事实。

## 6. 业务流程

```text
用户输入板块/个股/持仓
  ↓
数据健康门检查 A0/A1/A2/B1
  ↓
缺 A2：禁止 09:28 追强
  ↓
等待 09:30-09:35 承接数据
  ↓
检查价格位置、成交、板块共振、个股角色和风险收益比
  ↓
风控引擎计算仓位上限、1R、止损和失效条件
  ↓
输出计划、禁止动作、人工确认点和复盘字段
```

## 7. 功能需求

| 优先级 | 功能 | 输入 | 输出 | 验收标准 |
| --- | --- | --- | --- | --- |
| P0 | 数据健康门 | 日期、时间、工作流、标的、组合配置 | `action_permission_ceiling`、缺失字段 | 缺 A0/A1/A2/B1 时动作权限必须降级 |
| P0 | 缺 A2 降级 | A2 字段缺失或不可验证 | 禁止 09:28 追强 | 输出必须包含等待 09:35 承接条件 |
| P0 | 承接确认 | 开盘价、09:35 价格、VWAP、成交、板块状态 | 通过/不通过/继续观察 | 不得只因高开或涨幅给出买入 |
| P0 | 风控计划 | 止损位、账户风险预算、市场状态 | 仓位上限、1R、目标 R、失效条件 | 无止损不得输出买入或加仓 |
| P0 | 误用拦截 | 满仓、确定涨跌、自动下单请求 | 拒绝越权动作 | 不允许自动交易或收益承诺 |
| P1 | 日志字段 | 计划、概率、触发、用户 override | prediction/outcome/behavior 模板 | 可用于后续 Brier score 和行为风险复盘 |
| P1 | 角色分层 | 龙头/核心/中军/跟风代理 | 角色风险提示 | 弱跟风默认不得追强 |
| P2 | UI 展示 | 工作流结果 | 数据健康、权限、计划和复盘卡片 | 非技术读者能理解为什么降级 |

## 8. AI 输出契约

输出必须包含：

1. 事实：只写已提供或可验证的数据。
2. 推断：明确说明市场状态、板块共振、个股角色和不确定性。
3. 计划：操作、风格、触发、止损、目标 R、仓位上限、失效条件。
4. 禁止动作：缺数据、市场状态不允许、风险收益不足或用户越权时必须写明。
5. 复盘字段：预测事件、概率、expected R、结果记录方式和行为风险标签。

禁止输出：

1. 确定涨跌。
2. 自动下单。
3. 无来源事实。
4. 无止损买入。
5. 将历史回测包装成收益证明。

## 9. 异常与降级策略

| 异常 | 系统行为 |
| --- | --- |
| A1 实时行情不足 | 只输出手动核验清单，不给高置信交易动作 |
| A2 缺失 | 禁止 09:28 追强，降级为 09:35 承接确认 |
| B1 市场结构缺失 | 市场状态置信度不得高于中，降低仓位权限 |
| 消息来源过期或单一 | 标记低置信，不作为高置信催化 |
| 用户要求满仓或忽略止损 | 拒绝扩大风险，提示仓位和止损边界 |
| 用户要求自动下单 | 拒绝执行交易，只输出人工确认计划 |

## 10. 验收标准

| 验收项 | 标准 |
| --- | --- |
| 数据权限 | 缺 A2 时 09:28 不得输出追强动作 |
| 风险完整性 | 可执行计划必须包含触发、止损、目标 R、仓位上限、失效条件和不交易条件 |
| 证据边界 | 无来源、过期、传闻和资金流代理不得被写成确定事实 |
| 用户误用 | 自动下单、满仓诱导和确定收益请求必须被拦截 |
| 可复盘性 | 输出必须能生成 prediction/outcome/behavior 日志字段 |
| 运行验证 | `python3 tools/portfolio_validation.py --format markdown` 应通过全部 guardrail 用例 |
