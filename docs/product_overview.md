# A股研究与交易决策支持系统产品说明

## 1. 产品定位

本产品是一套面向 A 股短线与波段交易场景的研究和决策支持系统。它不替用户下单，也不承诺收益；核心职责是把高噪声、高时效、高风险的盘前和盘中判断，收敛成一套可核验、可执行、可复盘的决策流程。

系统服务的不是“寻找确定上涨的股票”这个伪命题，而是更实际的交易问题：

1. 今天市场环境是否允许承担新的风险。
2. 用户关注的板块是否具备主线、轮动、修复或退潮特征。
3. 用户给出的个股是否通过完整证据栈，而不是只靠概念标签或涨幅。
4. 当前持仓的原始逻辑是否仍成立，是否需要减仓、持有、切换或继续观察。
5. 如果判断错误，最大损失是多少，在哪里撤，什么情况下不交易。

因此，产品的第一性原则不是提高观点数量，而是提高决策质量。一个高质量输出必须同时满足四个条件：事实来源清楚、推理边界清楚、交易计划可执行、失败条件可复盘。

## 2. 目标用户与使用场景

目标用户是有主动交易需求、但容易被盘面波动和信息流干扰的 A 股交易者。典型特征包括：

1. 有明确持仓和观察池，需要在开盘前、盘中或尾盘做处理决策。
2. 会主动关注主题、政策、产业链和盘口，但容易被单一信号强化判断。
3. 需要更严格的仓位、止损、换仓和复盘纪律。
4. 接受概率化表达，不追求模型给出确定性结论。

核心使用场景分为五类：

| 场景 | 产品要回答的问题 | 输出结果 |
| --- | --- | --- |
| 09:28 集合竞价校正 | 今天能不能进攻，哪些结构有资格，开盘错了怎么撤 | 市场状态、提前放权、持仓事件预测、开盘执行表 |
| 14:30 尾盘判断 | 今日强度是否有隔夜价值，明天竞价要验证什么 | 尾盘概率、隔夜风险、次日验证清单 |
| 用户给定板块 | 这个方向是真主线、轮动机会，还是概念噪音 | 子方向拆解、龙头/中军/补涨/跟风、风险排序 |
| 用户给定个股 | 这只票能不能买、持有、减仓或放弃 | 个股证据栈、阶段判断、风险收益和操作计划 |
| 当前持仓管理 | 原逻辑是否增强、削弱或失效 | 持有、减仓、卖出、加仓或换仓条件 |

## 3. 产品核心原则

### 3.1 数据先于观点

所有交易结论都必须受数据等级约束。系统按 A0/A1/A2/B1/B2/B3/C 分层管理证据：

| 层级 | 内容 | 产品权限 |
| --- | --- | --- |
| A0 | 账户、持仓、现金、成本、风险预算 | 缺失时不能给仓位建议 |
| A1 | 实时价格、开高低、成交额、VWAP、均线、分时 | 缺失时不能给高置信个股计划 |
| A2 | 竞价成交、封单、撤单、盘口队列、竞价角色排序 | 只用于 09:28 提前放权；缺失时禁止追强和“竞价超预期”结论 |
| B1 | 市场宽度、涨跌停、连板高度、板块结构 | 缺失时市场状态置信度降级 |
| B2/B3 | 筹码、资金流、龙虎榜、融资、持有人数据 | 只作为概率修正，不作为单独买卖依据 |
| C | 公告、新闻、产业链、财报、调研材料 | 用于催化和原始逻辑更新 |

这套设计的关键价值是防止模型在数据不足时越权输出。数据不够时，系统不是用更多文字解释不确定性，而是直接降低可输出权限。

### 3.2 市场状态先于个股判断

系统先判断市场状态，再判断个股。当前模型使用五类市场状态：

1. 强进攻日：指数、成交、情绪和主线共振，只做龙头、中军和已验证强趋势。
2. 轮动日：指数不差但持续性不足，只适合低吸、强换弱和仓位管理。
3. 退潮日：高标、强势股或指数走弱，原则上不开新仓。
4. 冰点修复日：恐慌释放后开始修复，只允许核心小仓试错。
5. 混沌日：指数、情绪、板块信号冲突，默认降低仓位。

市场状态决定总仓位权限和新增风险权限。个股再强，也不能绕过市场状态和风控约束。

### 3.3 持仓没有特权

系统明确反沉没成本。一个股票已经亏损、已经研究过或已经持有，并不能成为继续投入资金的理由。

每次持仓评价都必须重新回答：

1. 原始买入或关注逻辑是增强、削弱、未变，还是失效。
2. 新增正面证据是什么。
3. 新增负面证据是什么。
4. 哪些利好已经被市场反映。
5. 继续持有的条件、减仓条件、卖出条件和可加仓条件分别是什么。
6. 新候选是否在预期强度、板块地位、流动性、止损距离和组合风险上明显优于现有持仓。

这使系统从“解释为什么还能拿”转向“重新证明是否值得拿”。

## 4. 核心工作流

### 4.1 09:28 集合竞价校正

09:28 是上午第一版可交易校正窗口。系统不依赖过早的静态晨报，而是基于市场状态、用户持仓、板块核心票、开盘后承接条件和可得 A2 竞价行为判断当天权限。

关键输出包括：

1. 数据等级和今日被禁止的动作。
2. 市场状态评分和仓位权限。
3. 持仓在 09:35、10:00、收盘三个窗口的事件预测。
4. 龙头、中军、补涨和跟风的共振情况；有 A2 时再加入竞价排序。
5. 开盘执行表：执行、观察、低吸、减仓、取消。

如果 A2 竞价数据缺失，系统只能输出 09:30-09:35 的承接确认条件，不能给 09:28 开盘追强结论。确认后的动作仍要同时满足市场状态、板块共振、VWAP/开盘价承接和止损距离。

### 4.2 14:30 尾盘预测与隔夜计划

14:30 用于判断当天资金行为是否具有收盘和隔夜价值。它不是简单的买入评分，而是对早盘预测进行复盘，并给出次日竞价验证条件。

关键输出包括：

1. 09:28 预测复盘：哪里对、哪里错、错误类型是什么。
2. 尾盘市场状态评分。
3. 持仓和观察股的强收概率、次日竞价延续概率、隔夜失败概率。
4. 扣除跳空风险后的 expected R。
5. 次日 09:28 必须验证的龙头、中军、跟风和持仓条件。

尾盘买入只有在市场权限、尾盘结构、止损距离和隔夜风险都通过时才允许。否则优先输出观察或次日验证。

### 4.3 用户给定板块/个股/持仓综合分析

用户临时给出的板块和个股会进入统一的综合分析流程，而不是直接被当成买入理由。

对用户给定板块，系统先拆子方向，再判断：

1. 是否有板块宽度和成交支持。
2. 龙头、中军、补涨、跟风是否形成结构。
3. 最新催化是否有来源，是否已经被价格反映。
4. 与用户当前持仓是否同向叠加风险，还是构成更优替代。

对用户给定个股，系统必须进入单股证据栈：

1. 实时盘口和分时位置。
2. K 线、均线、成交和流动性。
3. 板块角色和相对强弱。
4. 催化、基本面和最新边际驱动。
5. 筹码、持有人、资金流等可得修正项。
6. 止损距离、目标 R、仓位上限和不交易条件。

对当前持仓，系统强制做原始逻辑更新和未来期望比较，避免新机会与存量风险割裂。

## 5. 风控与仓位机制

本产品不把仓位当成信心表达。仓位由四个因素共同决定：

1. 市场状态允许的总仓位上限。
2. 从买入价到结构止损位的距离。
3. 单笔允许亏损预算。
4. 流动性和组合集中度。

基础公式是：

```text
可买仓位比例 = 单笔允许亏损比例 / 买入价到结构止损位的跌幅
```

系统的风控要求包括：

1. 买入和加仓必须先定义 1R。
2. 没有结构止损，不允许新增风险。
3. 短线持仓触发有效止损后，不允许补仓摊低成本。
4. 连续止损、单日亏损或计划外交易会触发降档或停手。
5. 强进攻日也只允许放大核心票，不允许重仓弱跟风。

这套机制的目标不是让每笔交易都正确，而是让错误的损失可控，并让连续错误不会扩大成账户级风险。

## 6. 证据、推理和计划的分离

系统输出必须分成三层：

| 层级 | 含义 | 示例 |
| --- | --- | --- |
| 事实 | 可以被行情、公告、截图或数据包验证 | 价格、成交额、均线、公告发布时间 |
| 推理 | 基于事实形成的结构判断 | 板块处于轮动、个股为中军、催化可能已反映 |
| 计划 | 在风险约束下的动作条件 | 站回关键位才持有，跌破结构线减仓 |

这种分层可以降低两类典型错误：

1. 把未经验证的传闻写成事实。
2. 把模糊观点直接转成买卖动作。

资金流、龙虎榜、筹码和持有人数据也按这个逻辑处理。它们可以成为修正项，但不能被写成“真实主力意图”的确定证据。

## 7. 概率、expected R 与校准

系统用概率和 expected R 组织交易计划，但不把模型概率包装成真实胜率。

标准表达为：

```text
expected R = 成功概率 × 目标R - 失败概率 × 1R - 噪音概率 × 噪音成本R - 跳空风险惩罚
```

一个可执行计划至少需要：

1. 基准概率来源。
2. 正向修正因子。
3. 负向修正因子。
4. 成功、失败、噪音三类概率。
5. 目标 R、止损 R 和期望 R。
6. 结果日志和错误归因字段。

如果样本不足，系统必须标注“待校准”，不能给伪精确胜率。预测日志和结果日志用于后续计算概率分桶、Brier score、expected-R 偏差和错误类型分布。

## 8. 产品边界

产品边界必须清晰，否则交易辅助系统很容易滑向不可控风险。

系统允许做：

1. 整理市场、板块、个股和持仓证据。
2. 给出有条件的交易计划。
3. 提醒止损、仓位和不交易条件。
4. 记录预测、结果和用户行为。
5. 复盘规则是否过严、过松或权重错误。

系统不允许做：

1. 自动下单。
2. 承诺收益或使用确定性涨跌语言。
3. 编造价格、公告、资金流或来源。
4. 在数据缺失时给高置信买入或加仓。
5. 因为用户已经亏损而建议继续持有或补仓。

这不是保守表述，而是产品安全性的核心设计。没有边界的智能体在交易场景中不是能力增强，而是风险放大器。

## 9. 衡量指标

产品不应优先用“推荐后涨没涨”作为核心指标。更合理的指标是决策质量和风险行为是否改善。

| 指标 | 含义 |
| --- | --- |
| 计划完整率 | 每个行动是否有触发、止损、目标、失效和不交易条件 |
| 数据越权拦截率 | 数据不足时是否成功降级 |
| 无止损交易率 | 用户是否仍出现没有结构止损的交易 |
| 计划外交易率 | 用户是否脱离系统计划冲动交易 |
| 用户 override 率 | 用户是否频繁绕过风控 |
| 结果日志完成率 | 预测是否能被复盘 |
| 概率校准误差 | 概率表达是否过度自信 |
| 复盘耗时 | 系统是否降低盘后复盘成本 |

这些指标比单次盈亏更适合作为产品健康度，因为它们能判断系统是否真的降低了错误决策和失控交易的概率。

## 10. 当前版本能力

当前版本已经形成较完整的本地工作流：

1. 组合配置校验：读取账户、持仓、观察池和风险参数。
2. 数据采集：支持尾盘批量数据包和单股深研数据包。
3. 数据健康门：根据 A0/A1/B1/09:35 承接等稳定主证据和 `config/decision_weights.json` 决定输出权限、稳定数据就绪分和动作权限上限。
4. 运行包生成：为 09:28、14:30、主题筛选、单股深研和用户综合分析生成可审计上下文。
5. 风控发动机：按结构止损和风险预算倒推仓位。
6. 预测模板：生成 prediction/outcome 日志结构。
7. 离线验证：用 37 条 guardrail 用例验证数据缺失、RAG、风控、用户误用、用户给定对象、开盘承接和计划完整性。
8. 历史阈值校准：用过去一个月公开数据验证 A1/B1 门槛和缺 A2 降级规则的初始合理性。
9. 历史权限回测：用 101 只主板样本股、57,558 个 stock-day 和 827 个开盘追强候选验证缺 A2 禁止 09:28 追强的风险控制有效性。
10. 过去三个月可靠性回测：用 99 只主板样本股、5,635 个 stock-day 和 60 个开盘追强候选检查近期市场窗口是否支持继续保留缺 A2 降级；新增机会错杀代理、市场状态分层、角色代理分层和 09:35 确认入口。该结果支持保守权限，并把放行对象收窄到核心/中军/趋势确认票，但样本不足以证明收益或放宽 09:28 权限。

当前能力的重点是把交易判断变成流程化、可审计、可校准的决策系统，而不是追求自动化交易闭环。

## 11. 演进问题的落地机制

产品演进不再停留在“后续建议”，而是已经拆成六个可执行机制。每个机制都对应一个本地命令、一个数据落点和一个降级规则。

| 演进问题 | 当前解决机制 | 数据落点 | 权限边界 |
| --- | --- | --- | --- |
| A2 竞价样本不足 | 生成手工竞价模板，并统计样本字段覆盖 | `data/manual/auction/{date}.json` | 核心字段不完整时，09:28 仍只能输出确认清单 |
| 09:35 承接样本不足 | 用公开分时 collector 连续记录持仓、观察池和当日核心票 | `reports/{date}-0935-tail-data.json` | 未确认承接前，不把候选升级为可执行买入 |
| prediction/outcome 样本不足 | 根据 prediction 生成 outcome 模板，强制记录 actual、result R 和 error type | `reports/predictions/`、`reports/outcomes/` | 无 outcome 匹配时，base rate 不能升级 |
| 行为日志缺失 | 生成 behavior 风险事件模板，记录计划外、无止损和 override | `reports/behavior/{date}-events.jsonl` | 没有行为日志时，不能证明风险行为下降 |
| 消息证据层不完整 | 生成消息证据 JSON，统计来源、时效、传闻和冲突 | `data/manual/messages/{date}.json` | 缺来源、过期或传闻不得进入高置信催化 |
| 报告过长、动作不清 | 增加短版决策简报，先输出数据等级、稳定数据就绪分、动作权限上限、风险和最小下一步 | `brief` 命令输出 | 数据等级 C/D 时只显示防守与补数动作 |
| 缺周度复盘 | 按日期区间汇总 A2、prediction/outcome、behavior 和 message evidence | `review weekly` 命令输出 | 样本不完整时只调整流程，不调整胜率参数 |

对应命令如下：

```bash
python3 tools/trading_assistant.py auction-template --date YYYY-MM-DD
python3 tools/trading_assistant.py auction-csv-template --date YYYY-MM-DD --codes 当日核心票1 当日核心票2
python3 tools/trading_assistant.py auction-import-csv --date YYYY-MM-DD --input data/manual/auction/YYYY-MM-DD.csv
python3 tools/trading_assistant.py auction-samples --start-date YYYY-MM-DD --end-date YYYY-MM-DD
python3 tools/trading_assistant.py auction-calibration --start-date YYYY-MM-DD --end-date YYYY-MM-DD
python3 tools/trading_assistant.py prediction outcome-template --date YYYY-MM-DD --automation auction
python3 tools/trading_assistant.py prediction behavior-template --date YYYY-MM-DD --automation auction
python3 tools/trading_assistant.py message-evidence template --date YYYY-MM-DD --codes 002156.SZ --themes 半导体
python3 tools/trading_assistant.py brief --date YYYY-MM-DD --time 0928 --automation auction
python3 tools/trading_assistant.py review weekly --start-date YYYY-MM-DD --end-date YYYY-MM-DD
```

这组机制解决的是“能不能稳定积累证据并约束输出”，不是“立刻证明交易收益”。产品演进的判断标准仍然是用户是否更少在低胜率环境中做高风险动作，是否更容易在交易前明确亏多少算错，以及是否能在交易后复盘为什么错。

补充规则：空模板不计入有效样本。`review weekly` 只统计已经填写 actual/result/error 的 outcome，以及已经填写动作、违规、执行或 override 信息的 behavior 事件，避免把“创建模板”误判成“完成复盘”。

## 12. 总结

这套产品的核心价值，是在信息噪声和交易冲动之间建立一层决策质量系统。

它不试图替代用户判断，而是要求每一次判断都经过同一套约束：市场状态、证据栈、数据权限、仓位风险、失效条件和复盘记录。对于 A 股这种情绪、题材、流动性和政策信息高度交织的市场，这种约束比单次观点更重要。

真正可持续的交易辅助产品，不应该让用户更频繁地下判断，而应该让用户更清楚地知道：什么时候可以出手，什么时候只能等待，什么时候必须承认判断错了。
