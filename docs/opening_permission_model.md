# Opening Permission Model

Last updated: 2026-05-28 Asia/Shanghai

本文定义 09:28 到 09:35 的开盘权限模型。它把 A2 竞价层从“唯一核心证据”调整为“提前放权证据”：A2 可以让系统更早判断，但产品有效性和风险权限的主证据应优先来自更稳定、可回测、可大样本获得的数据。

## 1. 产品判断

A2 的优势是早，不是天然更准。真实竞价成交额、09:20 后撤单、封单和队列信息对 09:28 判断有价值，但获取成本高、样本小、口径容易受截图和手工记录影响。

因此系统采用两层权限：

1. 主证据层：市场状态、板块共振、个股 09:30-09:35 承接、成交和风险收益比。
2. 提前放权层：真实 A2 竞价数据。它只决定能不能在 09:28 提前行动，不替代 09:35 承接验证。

## 2. 指标优先级

| 优先级 | 指标层 | 可得性 | 产品意义 | 权限作用 |
| --- | --- | --- | --- | --- |
| P0 | 市场状态和亏钱效应 | 高 | 决定当天能不能承担新增风险 | 总仓位和新增风险上限 |
| P0 | 板块强度与核心票共振 | 高 | 判断个股强度是否有主线支持 | 决定只做核心还是观察 |
| P0 | 09:30-09:35 开盘承接 | 高 | 验证高开、拉升或低吸是否被资金接受 | 缺 A2 时的主要替代确认 |
| P0 | 风险收益比和止损距离 | 高 | 判断错了亏多少、值不值得做 | 决定仓位上限和是否可交易 |
| P1 | 个股相对强弱和板块角色 | 高 | 区分龙头、中军、补涨、跟风 | 决定模式和优先级 |
| P1 | 成交额、换手、量比、流动性 | 高 | 判断资金确认还是缩量假突破 | 修正成功/失败概率 |
| P1 | K 线阶段、均线、箱体、前高 | 高 | 判断位置、压力和失效条件 | 定义触发与止损 |
| P2 | 公告、新闻、产业链证据 | 中 | 更新原始逻辑和催化强弱 | 进入催化修正，不单独触发交易 |
| P3 | 资金流、筹码、股东和 Level-2 | 中低 | 辅助判断拥挤度和结构 | 只能做弱修正 |
| P3 | 真实 A2 队列、撤单、封单 | 低 | 提前识别 09:28 强弱 | 只用于提前放权 |

## 3. 权限矩阵

| 数据状态 | 09:28 权限 | 09:35 后权限 | 禁止动作 |
| --- | --- | --- | --- |
| A0 + A1 + B1，无 A2 | 只允许输出确认条件 | 若 09:35 承接、板块共振、止损距离同时通过，可进入小仓或标准计划 | 禁止 09:28 追强，禁止“竞价超预期” |
| A0 + A1 + A2 + B1 | 可输出提前计划和小仓/标准权限 | 仍需被 09:35 承接验证；验证失败立即取消 | 禁止跳过止损和市场状态 |
| A0 + A1，无 B1 | 只允许个股观察和人工核验 | 市场状态置信度不得高于中 | 禁止把个股强度当成市场共振 |
| A0 缺失 | 只能输出研究清单 | 不能给仓位 | 禁止买入、加仓、减仓建议 |
| A1 缺失 | 只能输出防守和补数清单 | 不能做盘中高置信动作 | 禁止高置信买入或加仓 |

## 4. 09:35 承接确认

缺 A2 时，系统不应为了保留机会而直接放宽 09:28 权限。更稳定的做法是把候选降级为 09:35 确认。

最小确认条件：

1. 个股 09:35 价格不低于开盘价，且不弱于当时 VWAP。
2. 板块核心票同步承接，不是单只后排脉冲。
3. 市场状态不是退潮或强亏钱效应。
4. 买入价到结构止损的距离仍能给出正 expected R。
5. 若高开后快速回落、跌破开盘价或低于 VWAP，确认失败。

2026-05-28 三个月回测新增角色代理分层后，执行规则进一步收紧：

1. 弱跟风代理组误放行率为 100.0%，默认不得追强；即使 09:35 收回，也只能进入观察或小仓验证，不给标准仓位。
2. 龙头/核心代理组和趋势/中军代理组才允许进入 09:35 放行评估，但仍必须通过 VWAP、板块共振和止损距离。
3. 机会错杀代理为 25.0%，说明缺 A2 拦截后不能简单丢弃候选；必须把核心/中军候选放入 09:35 重新筛选。
4. 当前三个月回测没有稳定显式 09:35 price/VWAP 样本，因此 09:35 confirmation lift 仍待后续分钟线或授权数据验证。

本地可用命令：

```bash
python3 tools/trading_assistant.py collect tail-data --date YYYY-MM-DD --time 0935 --codes 当日核心票1 当日核心票2
python3 tools/trading_assistant.py data-health --date YYYY-MM-DD --time 0935 --automation auction
python3 tools/trading_assistant.py brief --date YYYY-MM-DD --time 0935 --automation auction
```

`collect tail-data` 在 09:35 使用的是同一套公开行情和分时接口。它不是 A2 替代品，但比手工竞价截图更容易形成连续样本。

## 5. A2 保留方式

A2 继续采集，但采集目标收敛为“提前放权校准”，不是证明长期收益。

最低核心字段：

1. `auction_price`
2. `auction_amount_cny`
3. `post_0920_cancel_signal`
4. `role_signal`

可选增强字段：

1. `auction_change_pct`
2. `auction_volume_lots`
3. `seal_amount_cny`
4. `bid_queue_signal`
5. `ask_queue_signal`

前 20 个交易日只采持仓、观察池和当日板块核心票。20-60 个核心完整样本后，再比较 A2 确认组和非 A2 组的误放行率、09:35 证伪率和 expected-R 偏差。若 A2 没有显著降低这些风险，不放宽 09:28 权限。

## 6. 证据链表述

公开产品证据应使用以下口径：

> 缺 A2 禁止 09:28 追强，不是主观保守，而是因为缺少真实竞价确认时，提前追强无法证明自己优于等待 09:35。系统用大样本公开历史数据验证“等待承接确认”的风险权限价值；真实 A2 继续作为提前放权的增量证据，通过 20-60 日样本校准。

该口径验证的是风险权限纪律，不证明长期收益，也不证明真实 Level-2 队列、撤单和封单因子的独立收益。
