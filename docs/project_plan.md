# Project Plan｜从 MVP 到生产化试点

## 1. 计划定位

本文档展示 A 股投资辅助决策 Agent 的项目推进方式。当前仓库是个人主导的本地 MVP 和公开作品集，不声称已经完成真实金融生产上线。这里的计划用于说明如果进入团队交付阶段，如何把需求、设计、开发、验收、灰度和指标跟进串成闭环。

## 2. 推进原则

1. 先证明数据边界和风险边界，再扩大功能。
2. 先做单链路可审计，再做多 Agent 编排。
3. 先跑 guardrail 和 outcome 校准，再讨论放宽交易权限。
4. 所有高风险输出保留人工确认，不接自动下单。
5. 数据授权、日志审计和隐私隔离必须早于生产化试点。

## 3. 阶段计划

| 阶段 | 任务 | 角色协作 | 验收物 | 主要风险 |
| --- | --- | --- | --- | --- |
| 1. 问题定义 | 明确目标用户、交易时段、动作边界和失败模式 | PM、投研、风控 | 问题定义、用户流程、边界清单 | 把产品误写成荐股或自动交易 |
| 2. PRD 与流程 | 输出 PRD、输入输出、异常状态、验收标准和埋点 | PM、研发、测试 | `docs/prd_excerpt.md`、流程图、埋点表 | 需求只停留在概念 |
| 3. 数据与权限 | 接入或模拟 A0/A1/A2/B1 数据，建立健康门 | 数据、后端、PM | 数据字段表、`action_permission_ceiling` | 数据时效、授权和字段缺失 |
| 4. Agent 工作流 | 编写 Prompt contract、运行包和输出模板 | PM、算法、后端 | `prompts/*.md`、run packet、CLI | 模型越权、幻觉和过度自信 |
| 5. 风控与日志 | 实现仓位、1R、止损、失效和复盘日志 | PM、后端、风控 | 风控配置、prediction/outcome/behavior 模板 | 风控被自然语言绕过 |
| 6. 验证与回测 | 跑 guardrail、RAG 证据测试、历史权限压力测试 | PM、测试、数据 | 37 条验证、回测报告、失败案例 | 样本不足或过拟合 |
| 7. Demo 与验收 | 展示工作台、截图、用户路径和验收标准 | PM、前端、设计 | 静态 Demo、README、Project Proof | 非技术读者看不懂 |
| 8. 灰度试点 | 小范围记录真实 prediction/outcome/behavior | PM、数据、风控 | 指标看板、反馈标签、周报 | 真实用户不写 outcome 或 override 偏高 |
| 9. 生产化评估 | 评估数据授权、延迟、成本、监控和合规 | PM、工程、合规 | 上线评审、风险清单、SLA 方案 | 过早承诺生产能力 |

## 4. 建议里程碑

| 周期 | 里程碑 | 退出标准 |
| --- | --- | --- |
| Week 1 | 需求和边界冻结 | PRD、非目标、误用场景和验收标准完成 |
| Week 2 | 数据健康门和运行包完成 | 缺 A0/A1/A2/B1 可稳定输出权限上限 |
| Week 3 | Agent 输出契约完成 | 计划字段完整，禁止动作可被测试覆盖 |
| Week 4 | Guardrail 验证完成 | 数据缺失、RAG、风险、用户误用和计划质量用例通过 |
| Week 5 | Demo 和项目证明完成 | 非技术读者能理解工作流和边界 |
| Week 6-8 | 小样本试点 | 收集 prediction/outcome/behavior 和反馈标签 |
| Week 9+ | 生产化评审 | 决定是否接入授权数据、服务化、监控和灰度 |

## 5. 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| A2 竞价数据不可得 | 无法安全支持 09:28 追强 | 默认降级到 09:35 承接确认 |
| 模型编造事实 | 误导用户判断 | 事实必须来自数据包或引用，缺来源降级 |
| 输出过度自信 | 用户低估风险 | 强制概率、失效条件和不交易条件 |
| 用户绕过风控 | 行为风险上升 | 记录 override，连续越权提高确认成本 |
| 样本过少 | 指标不可泛化 | 明确 small-sample boundary，继续积累 outcome |
| 数据源延迟 | 盘中不可用 | 缓存、fallback 和超时降级 |
| 成本过高 | SaaS 化不可持续 | 规则优先、RAG 缓存、限制模型调用步数 |
| 合规误读 | 被理解为投资建议或自动交易 | 明确 research only、human-in-the-loop 和风险声明 |

## 6. 项目会议与协作机制

生产化试点时建议使用轻量推进节奏：

| 节奏 | 目的 | 输出 |
| --- | --- | --- |
| 每日盘后 15 分钟 | 复盘当日数据缺口、输出问题和用户反馈 | issue list、次日修复项 |
| 每周评审 | 汇总 guardrail、outcome、override 和成本指标 | 周报、优先级调整 |
| 每次发版前 | 检查隐私、数据授权、风控和测试 | release checklist |
| 每次规则调整后 | 防止为了增加机会而放松风险边界 | 回测对比、失败样本 |

## 7. Definition Of Done

一个工作流只有同时满足以下条件，才算达到可试点状态：

1. 有明确用户场景和非目标。
2. 有可执行 PRD、输入输出和异常状态。
3. 数据健康门能给出机器可读权限上限。
4. AI 输出契约覆盖事实、推断、计划、风险和复盘字段。
5. Guardrail 用例覆盖关键误用和数据缺失场景。
6. 输出不自动下单、不承诺收益、不绕过风控。
7. 计划可写入 prediction/outcome/behavior 日志。
8. 有上线指标、反馈标签和下一轮迭代规则。
